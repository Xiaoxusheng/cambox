## 1. 项目概述

### 1.1 背景

计划购买一台支持 ONVIF/RTSP 的网络方块摄像头（300万/500万/800万，¥159 档）。**软件先行**：在相机到手前，用模拟视频源把整套监控系统开发、验证完毕；相机到手后只修改配置文件即可接入，零代码改动。

### 1.2 目标

一个可 7×24 运行的单机监控服务：

> 取流 → 实时预览 + 移动侦测 → 事件记录 → 循环录像 → Web 面板（预览/事件/录像/设置）

### 1.3 设计原则

- 单二进制部署（前端 embed 进二进制），唯一外部依赖是本机 FFmpeg（已确认安装且带 libx264）
- FFmpeg 子进程作为统一解码引擎，Go 不做协议解析，不引入 cgo
- 正确性 > 稳定性 > 安全 > 可维护性 > 性能 > 界面

## 2. 需求规格

### 2.1 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | 多源取流 | 支持 4 种来源：`synthetic`(内置测试画面)、`rtsp`、`file`(视频文件)、`dshow`(Windows 摄像头)。断线自动重连，重连间隔可配，重启次数与最后错误可见 |
| FR-2 | 实时预览 | MJPEG 流，浏览器无需插件直接观看；无帧时前端显示"信号丢失" |
| FR-3 | 移动侦测 | 帧差法（降采样灰度 + absdiff + 阈值 + 像素计数 + 外接框），参数可调（阈值/最小面积/冷却时间），事件自动保存标注缩略图 |
| FR-4 | 事件管理 | JSONL 按月分文件存储，API 分页查询（新→旧），内存保留最近 5000 条 |
| FR-5 | 循环录像 | 按时长分段 mp4。rtsp 源用 `-c copy` 流复制（零转码）；其他源用 libx264 编码。按"保留天数 + 容量上限"双策略自动清理 |
| FR-6 | 抓拍 | 面板手动抓拍，保存到 snapshots/manual/ |
| FR-7 | Web 面板 | 单页：实时预览、运行状态、事件流、录像列表、设置修改（热更新生效） |
| FR-8 | 配置 | YAML 文件 + API 热更新（motion/record 两组参数），持久化回 YAML |

### 2.2 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 稳定性 | ffmpeg 进程异常退出自动重启（指数退避 1s→2s→4s→…上限 30s）；主服务优雅关闭（HTTP→取流→录像） |
| NFR-2 | 并发安全 | 所有 goroutine 有 ctx 生命周期；`go test -race` 通过；无泄漏 |
| NFR-3 | 性能 | 720p@25fps 输入下：MJPEG ≥10fps，单帧检测 ≤50ms，内存稳定无无界增长 |
| NFR-4 | 安全 | 默认只监听 127.0.0.1；静态文件服务防路径穿越（http.FileServer）；不硬编码任何密钥 |
| NFR-5 | 可观测 | slog 结构化日志；ffmpeg stderr 保留最近 50 行并通过 API 暴露 |
| NFR-6 | 可测试 | 核心逻辑（检测/清理/配置/存储）有单元测试，不依赖 ffmpeg |

### 2.3 明确不做（范围外，含升级路径）

> v1.1 扩展计划见 [docs/功能扩展提案.md](docs/功能扩展提案.md)（Arco Design 前端重构 + P0/P1/P2 功能清单，待确认范围）。

| 不做 | 升级路径 |
|---|---|
| AI 检测(YOLO/人形) | detector 包预留 `Detector` 接口，后续新增实现替换 |
| 通知推送(钉钉/TG/Bark) | store.Append 处或 pipeline 事件出口加 notifier 模块 |
| 录像网页回放播放器 | 已有 mp4 分段 + /media 下载，接入 hls.js/video 标签即可 |
| 多摄像头 | pipeline/source 实例化多份 + 配置改列表 |
| 登录鉴权 | 加 middleware 层；**公网部署必须先做** |

| Goroutine | 启动者 | 退出条件 | 错误处理 |

## 4. 模块设计

目录：`cmd/server/main.go` + `internal/{config,store,source,detector,recorder,pipeline,server}`。小项目不做多余分层；handler 内不写业务逻辑。

### 4.2 store 包（事件存储）

**事件结构**（JSONL 每行一条，文件 `data/events-YYYYMM.jsonl`）：

```json
{"id":42,"time":"2026-09-28T20:15:03+08:00","type":"motion","score":1836,"image":"/media/snapshots/ev-20260928-201503-042.jpg"}
```

**接口**（无数据库；append 即写盘，崩溃安全）：

```go
type Event struct { ID int64; Time time.Time; Type string; Score int; Image string }
func Open(dir string, maxEvents int) (*Store, error)   // 扫描目录加载, 内存保留最新 maxEvents 条
func (s *Store) Append(typ string, score int, image string) (Event, error) // id 自增, 按月落盘
func (s *Store) List(limit, offset int) ([]Event, int) // 新→旧, limit≤100, 返回 total
func (s *Store) Count() int
```

### 4.3 source 包（取流）

**帧**：BGR24 裸帧 `Frame{W, H int; Data []byte}`（Data 长度恒为 W×H×3）。

**帧槽**（单写多读）：source 写线程持写锁 memcpy 进槽位；读者 `Snapshot(dst []byte) (Frame, bool)` 拷出（含序号，用于判断新帧）。另维护：connected、fps（最近 3s 帧数滑动窗口）、重启次数、lastError。

**ffmpeg 解码命令**（stderr→50 行环形缓冲；`exec.CommandContext` 保证 ctx 取消即杀进程）：

| type | 命令 |
|---|---|
| synthetic | `ffmpeg -hide_banner -loglevel warning -re -f lavfi -i testsrc2=size={W}x{H}:rate={fps} -pix_fmt bgr24 -f rawvideo pipe:1` |
| rtsp | `ffmpeg -hide_banner -loglevel warning -rtsp_transport tcp -rw_timeout 8000000 -i {url} -pix_fmt bgr24 -f rawvideo pipe:1` |
| file | `ffmpeg -hide_banner -loglevel warning -re -i {file} -pix_fmt bgr24 -f rawvideo pipe:1` |
| dshow | `ffmpeg -hide_banner -loglevel warning -f dshow -i video={device} -pix_fmt bgr24 -f rawvideo pipe:1` |

**状态机**：`disconnected → starting → connected → (读失败/EOF) disconnected →…`；run 循环：open → readLoop(逐帧 `io.ReadFull` 固定长度) → 退出则标记断开、sleep 重连间隔。

### 4.4 detector 包（移动侦测）

**算法**（纯 Go，无依赖，可单测）：

1. 全帧 BGR → 降采样灰度图（宽 downscale_width，最近邻采样，灰度=0.299R+0.587G+0.114B）
2. 与上一帧 absdiff，像素 |Δ|>threshold 记为变化像素
3. 变化像素数 ≥ min_area → 触发；同时计算变化区域外接框（映射回原分辨率）
4. 触发后冷却 cooldown_sec 内不重复触发
5. 事件缩略图：原帧拷贝上画 2px 绿框 → JPEG(q85) 存 snapshot_dir/events/

**接口**（预留 YOLO 替换位）：

```go
type Detection struct { Score int; Rect image.Rectangle }
type Detector interface { Detect(f *source.Frame) (Detection, bool) }   // Detect 内部维护前后帧状态
// v1 实现: NewMotion(cfg MotionConfig) ; SetConfig(cfg) 支持热更新
```

### 4.5 recorder 包（录像）

**双模式**（按 source.type 自动选择）：

| 模式 | 适用 | 命令 |
|---|---|---|
| copy | rtsp | `ffmpeg -hide_banner -loglevel warning -rtsp_transport tcp -i {url} -map 0 -c copy -f segment -segment_time {seg} -reset_timestamps 1 -strftime 1 {dir}/%Y-%m-%d_%H-%M-%S.mp4` |
| encode | synthetic/file/dshow | `ffmpeg -hide_banner -loglevel warning -f rawvideo -pixel_format bgr24 -video_size {W}x{H} -framerate {fps} -i pipe:0 -c:v libx264 -preset veryfast -crf 26 -pix_fmt yuv420p -f segment -segment_time {seg} -reset_timestamps 1 -strftime 1 {dir}/%Y-%m-%d_%H-%M-%S.mp4` |

- encode 模式：run 循环按目标 fps 从帧槽 Snapshot → 写 ffmpeg stdin；stdin 写失败/进程退出 → 退避重启
- `record.enabled=false`（含热切）→ 杀进程、不重启；状态暴露 current_file
- **清理器**（每 1h）：先删过期（>retention_days，含快照目录）；再判容量：超 max_disk_gb 则从最旧开始删除直至达标；每次删除记 slog

### 4.6 pipeline 包（编排）

职责：装配 source/detector/recorder/cleaner；持有运行时设置（atomic.Pointer）；Start(ctx) 启动全部 goroutine（WaitGroup 管理），Stop 由 ctx 取消触发。检测循环 150ms tick 从帧槽取帧（检测频率 ~6.7Hz，低于源帧率，省 CPU）。

### 4.7 server 包（HTTP）

**统一 JSON 响应**：`{"code":0,"message":"success","data":{...}}`；错误 `code≠0`（400 参数 / 404 / 500 / 503 无帧）。前端资产 `internal/server/web/` 经 `go:embed` 提供。

**路由表**：

| 方法 | 路径 | 说明 | 响应 data |
|---|---|---|---|
| GET | / | 面板页面 | HTML |
| GET | /api/status | 运行状态 | 见下 |
| GET | /api/stream.mjpeg | MJPEG 实时流 | multipart/x-mixed-replace |
| GET | /api/snapshot | 当前帧 JPEG（不落盘） | image/jpeg |
| POST | /api/snapshots | 手动抓拍落盘 | `{"file":"snap-...jpg","url":"/media/snapshots/..."}` |
| GET | /api/events?limit&offset | 事件分页 | `{"items":[Event...],"total":n}` |
| GET | /api/recordings | 录像文件列表 | `{"items":[{"name","size_bytes","modified"}],"total_size_bytes":n}` |
| GET | /media/recordings/{name} / /media/snapshots/{name} | 文件服务 | 文件（http.FileServer 防穿越） |
| GET | /api/config | 读 motion+record | `{"motion":{...},"record":{...}}` |
| POST | /api/config | 全量热更新 | 更新后的同结构 |

**GET /api/status 示例**：

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
