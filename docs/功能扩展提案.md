## 一、新前端（Arco Design 重构）

**技术**：Vite + React + @arco-design/web-react + React Router；构建产物 `npm run build` 后仍 go:embed 进 Go 二进制，保持单文件部署；开发时 Vite 代理 /api。

**页面地图**（从单页升级为侧边导航多页）：

| 路由 | 页面 | 内容 |
|---|---|---|
| /dashboard | 概览 | 状态卡、磁盘水位、今日事件趋势图、最新事件 |
| /live | 实时监控 | 大画面、控制条、抓拍、ROI 绘制入口 |
| /playback | 录像回放 | 日期选择 + 24h 时间轴（录像段/事件刻度）+ 播放器 + 倍速 |
| /events | 事件中心 | 筛选(类型/日期)、大图预览、批量删除、跳转回放 |
| /recordings | 录像管理 | 表格、存储水位、下载/删除、片段导出 |
| /settings | 设置中心 | Tab 分组：摄像头/侦测/录像存储/通知/布防日程 |
| /logs | 系统日志 | 实时日志流(SSE) |

## 三、技术要点（确认后写入开发文档）

- **回放**：录像已是标准 mp4 分段，前端 `<video>` 直接播；时间轴数据来自 /api/recordings + 事件时间。
- **多码流**：`camera.rtsp`(主) + `camera.sub_rtsp`(子) 两个 ffmpeg 解码实例；子码流供检测/预览，主码流仅供 copy 录像。
- **ROI**：归一化矩形存配置；detector 加掩码过滤；前端在截图上画框。
- **推送**：Go 原生 HTTP webhook；事件带缩略图时通过渠道能力决定（钉钉/企微 markdown 图需公网可达，默认发文字+时间+分数，Bark 可带图）。
- **日程**：`schedules: [{days, start, end, actions:[motion,record]}]`，pipeline 每分钟评估。
- **AI**：本地 Python 微服务跑 YOLOv8n（ultralytics），Go 发 JPEG 收框；不引入 cgo；CPU 可跑（~100ms/帧），有 N 卡更快。
